בדיקה נוספת — 04.08.2026

תיקון טעינת env ב־Vite
Vite קרא רק VITE_* ולכן עם קובץ env שמכיל NEXT_PUBLIC_* נכנס למצב דמו. נוסף fallback מפורש ל־NEXT_PUBLIC_SUPABASE_URL ו־NEXT_PUBLIC_SUPABASE_ANON_KEY.
בדיקת UI בדפדפן הפתוח
העמוד החי נטען. 12/12 לשוניות נפתחו. סטטוס השמירה הציג “נשמר בשרת”. הנתונים הקיימים הופיעו גם בדשבורד וגם בחוברת.
E2E login
הבדיקה משתמשת כעת רק ב־E2E_EMAIL ו־E2E_PASSWORD וטוענת את .env. ההרצה נעצרה לפני המסכים כי Supabase החזיר Invalid login credentials. אין סימון ירוק עד שיוזן משתמש בדיקה קיים בסביבת Supabase שמוגדרת ב־env.
RLS collision במשכנתאות
בדיקת UI זיהתה כתיבות חוזרות שנחסמו. נוספה בדיקת בעלות לפני upsert ומיגרציית מזהה דטרמיניסטית למזהה שהגיע מ־household אחר. RLS נשאר פעיל; אין עקיפת הרשאות.
Health endpoint
בדיקת health החזירה 429 אחרי burst של בקשות UI. החרגתי רק /api/health ממגבלת הבקשות, כדי ש־liveness/monitoring יישאר זמין; כל API עסקי נשאר מוגבל.

מה בוצע

הקשחת API
נוספו Security Headers דרך Helmet, הוסרה חתימת Express, נוסף Rate Limit גלובלי ל־API, ו־CORS מאשר רק origins מוגדרים.
הקטנת שטח תקיפה
Body JSON גלובלי ירד מ־10MB ל־2MB. העלאות קבצים עדיין מוגבלות ל־20MB ובדיקות magic-bytes קיימות במסלולים.
הקשחת multipart
נוספו מגבלות על מספר קבצים, שדות, parts וגודל שדה. חריגה מחזירה 413 כללי ולא stack trace.
הגנת XLSX
נבדק מבנה ZIP לפני parser: מספר entries, גודל מרכזי, יחס דחיסה וגודל פתיחה מצטבר. קובץ חשוד נחסם.
מניעת דליפת מידע
שגיאות 500 מחזירות internal_error בלבד. פרטי DB ו־stack trace נשארים בלוג השרת.
סנכרון
כשל כתיבה מרחוק כבר לא נחשב הצלחה שקטה: נשלח אירוע verdant:sync:result ומדווחת שגיאה.
Tenant guard
סנכרון מרחוק מקבל household ID רק אם הוא UUID תקין. ערך מזויף או פגום עוצר כתיבה.
RPC מצב לקוח
נוספה migration שמקשיחה את upsert_client_state: search_path קבוע, בדיקת מפתח, נעילה אטומית ו־grant מפורש למשתמשים מחוברים בלבד.
מסלול כתיבה קנוני
שמירת client_state עוברת רק דרך API מאומת ו־RPC אטומי. הוסר fallback ישיר מהדפדפן ומסלול legacy; כשל נשאר בתור retry.
CI
נשמר workflow קיים והורחב ל־typecheck ו־build לפרונט ולבק, והרצת audit כתוצאה מדווחת. Lint עדיין דורש ניקוי ייעודי כי אין לו כרגע קונפיגורציה תקינה.
שומר אבטחה אוטומטי
נוסף security:check שסורק migrations, RLS, RPC מוגן, ו־service_role בפרונט. הבדיקה עברה.
חוברת משפחה ללא cache מקומי
קריאת החוברת מגיעה מ־Supabase דרך GET מאומת; כתיבה עוברת דרך POST קנוני ו־RPC. אין שמירת נתוני חוברת ב־localStorage.
מבנה לשוניות
נוספו כותרות וסעיפי־על לפי ה־template, טבלת שאלון, מטרות, חובות/מאזן ותצוגת 12 חודשים עם תכנון וביצוע לתזרים ולעסק.
מספרים ב־RTL
מספרים, מטבע וסימן מינוס עטופים ב־LTR כדי שמינוס יוצג משמאל: -2,500,000 ₪.

מה עדיין דורש טיפול

הרשאות DB רחבות
קיימים grants כלליים ל־authenticated. ה־RPC המרכזי הוקשח, אבל צריך לצמצם לפי טבלה/פעולה לאחר מיפוי כל המסכים, אחרת אפשר לשבור את האפליקציה.
נתוני מודולים ותיקים
נמצאו 108 קבצים עם שימוש ב־localStorage. חוברת המשפחה עצמה כבר אינה שומרת cache מקומי, אבל נדרשת מיגרציה מדורגת של שאר המודולים לשרת, עם בדיקות לפני כל מעבר.
מסלולי כתיבה בתחומים אחרים
מצב client_state נסגר למסלול קנוני. עדיין צריך להחיל אותו דפוס על תחומי הנתונים הישירים האחרים.
Dependencies
postcss עודכן אל מחוץ לטווח החולשה. בדיקת npm audit הנוכחית מדווחת 5 חולשות production (2 high, 2 moderate, 1 low): בעיקר xlsx ללא תיקון upstream ותלויות transitve. קיים בידוד ובדיקת מבנה לקבצי XLSX, אך עדיין צריך עדכון או החלפה של parser ובדיקת regression.
Production
צריך להוסיף CI branch protection, backup/restore test, schema drift check, ניטור, alerting ו־rollback.
אימות מלא
חוברת המשפחה נבדקה בפועל עם session מחובר. בדיקות E2E אוטומטיות מלאות למסכים מאומתים עדיין דורשות פרטי בדיקה תקינים; המשתמש הקיים החזיר Invalid login credentials.

סדר עבודה מומלץ להמשך

  1. להחליף xlsx או להעביר parsing מסוכן לשירות מבודד.
  2. למפות כל table ו־policy ולצמצם grants.
  3. להגדיר API/commands קנוניים ו־transactions.
  4. להעביר את שאר המודולים מ־localStorage לקריאה וכתיבה ישירה לשרת, ללא cache מקומי.
  5. להוסיף בדיקות tenant isolation לכל route ולכל table.
  6. להגדיר backup, restore, monitoring ו־rollback אמיתיים.
