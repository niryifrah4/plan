מצב: בוצעו תיקונים בטוחים ומאומתים. נשארו עבודות עמוקות שדורשות תכנון DB/Production ולא בוצעו באופן עיוור.

מה בוצע

הקשחת API
נוספו Security Headers דרך Helmet, הוסרה חתימת Express, נוסף Rate Limit גלובלי ל־API, ו־CORS מאשר רק origins מוגדרים.
הקטנת שטח תקיפה
Body JSON גלובלי ירד מ־10MB ל־2MB. העלאות קבצים עדיין מוגבלות ל־20MB ובדיקות magic-bytes קיימות במסלולים.
הקשחת multipart
נוספו מגבלות על מספר קבצים, שדות, parts וגודל שדה. חריגה מחזירה 413 כללי ולא stack trace.
מניעת דליפת מידע
שגיאות 500 מחזירות internal_error בלבד. פרטי DB ו־stack trace נשארים בלוג השרת.
סנכרון
כשל כתיבה מרחוק כבר לא נחשב הצלחה שקטה: נשלח אירוע verdant:sync:result ומדווחת שגיאה.
Tenant guard
סנכרון מרחוק מקבל household ID רק אם הוא UUID תקין. ערך מזויף או פגום עוצר כתיבה.
RPC מצב לקוח
נוספה migration שמקשיחה את upsert_client_state: search_path קבוע, בדיקת מפתח, נעילה אטומית ו־grant מפורש למשתמשים מחוברים בלבד.
CI
נשמר workflow קיים והורחב ל־typecheck ו־build לפרונט ולבק, והרצת audit כתוצאה מדווחת. Lint עדיין דורש ניקוי ייעודי כי אין לו כרגע קונפיגורציה תקינה.
שומר אבטחה אוטומטי
נוסף security:check שסורק migrations, RLS, RPC מוגן, ו־service_role בפרונט. הבדיקה עברה.

מה עדיין דורש טיפול

הרשאות DB רחבות
קיימים grants כלליים ל־authenticated. ה־RPC המרכזי הוקשח, אבל צריך לצמצם לפי טבלה/פעולה לאחר מיפוי כל המסכים, אחרת אפשר לשבור את האפליקציה.
localStorage כמקור אמת
עדיין קיימת ארכיטקטורת localStorage-first. צריך להפוך את Supabase למקור האמת, עם cache מקומי בלבד ומצב שמירה גלוי.
מסלולי כתיבה מרובים
יש כמה מנגנוני sync. צריך command קנוני לכל תחום ו־transaction/idempotency לשינויים מורכבים.
xlsx
ה־dependency מדווחת חולשות Prototype Pollution ו־ReDoS. צריך להחליף או לבודד את parser, במיוחד בקבצים שמגיעים ממשתמשים.
Production
צריך להוסיף CI branch protection, backup/restore test, schema drift check, ניטור, alerting ו־rollback.
אימות מלא
בדיקות UI מלאות למסכים מאומתים דורשות session בדפדפן. כרגע נבדק רק שער ההתחברות.

סדר עבודה מומלץ להמשך

  1. להחליף xlsx או להעביר parsing מסוכן לשירות מבודד.
  2. למפות כל table ו־policy ולצמצם grants.
  3. להגדיר API/commands קנוניים ו־transactions.
  4. להפוך Supabase למקור אמת ולשמור localStorage כ־cache.
  5. להוסיף בדיקות tenant isolation לכל route ולכל table.
  6. להגדיר backup, restore, monitoring ו־rollback אמיתיים.
